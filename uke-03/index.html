Lab · 60 min

Tags, locks og Azure Policy

Ingen av Learn-øvelsene dekker governance-delen av studieguiden, så her er en egen lab. Hvert steg er en oppgave du løser i portalen. Står du fast, eller vil du sjekke resultatet, ligger kommandoen under Vis kommando. Del A er tags og locks, del B er Azure Policy i Bicep, og del C er kostnad og management groups. Fasiten ligger under labben.

Før møtet

Samme oppsett som i uke 2: portalen i et privat vindu med lab-brukeren, og az lokalt med kursprofilen eller i Cloud Shell. Lag en mappe til labben, og sett variablene én gang: 

mkdir uke-03
cd uke-03
$NAVN = "<fornavn>"      # små bokstaver, f.eks. svein-tore
$RG = "rg-uke03"
$RG2 = "rg-uke03-flytt"

Tjenestene i portalen finner du raskest i søkefeltet øverst.

Del A — Subscription, tags og locks (ca. 20 min)

0. Registrer resource providers

Hvorfor: en subscription kan bare bruke en tjeneste når resource provideren for den er registrert. Policy-compliance og Advisor er ikke registrert hos oss ennå. Det tar et par minutter, så start nå.

Oppgave: åpne subscriptionen din → Resource providers, og registrer Microsoft.PolicyInsights og Microsoft.Advisor. Status går fra Registering til Registered.

Vis kommando
az provider register --namespace Microsoft.PolicyInsights
az provider register --namespace Microsoft.Advisor
az provider show --namespace Microsoft.PolicyInsights --query registrationState -o tsv

1. Resource group med tags

Hvorfor: tags er nøkkel og verdi som brukes til kostnadsfordeling og oversikt. Taggen kostnadssted går igjen i hele labben.

Oppgave: lag rg-uke03 i Norway East med taggene eier = fornavnet ditt og kostnadssted = 1234.

Vis kommando
az group create --name $RG --location norwayeast --tags eier=$NAVN kostnadssted=1234 --query tags

2. En ressurs i gruppen

Hvorfor: tags arves ikke. Det spør eksamen om.

Oppgave: lag en network security group (NSG) som heter <fornavn>-nsg, i rg-uke03, uten tags. Den er gratis. Se så på taggene til NSG-en. Den har ingen, selv om resource groupen har to. I steg 9 lager vi en policy som gir nye ressurser taggen automatisk.

Vis kommando
az network nsg create -g $RG -n "$NAVN-nsg" --query NewNSG.tags

3. Merge og Replace

Hvorfor: portalen legger bare til tags. Med az og PowerShell kan du også erstatte alle på én gang, og da forsvinner de du hadde. Eksamen spør hvilken kommando som beholder dem.

Oppgave: dette steget gjør du med az, fordi forskjellen bare finnes der.

$NSG = az network nsg show -g $RG -n "$NAVN-nsg" --query id -o tsv
az tag update --resource-id $NSG --operation Merge --tags miljo=lab --query properties.tags
az tag update --resource-id $NSG --operation Merge --tags app=web --query properties.tags
az tag update --resource-id $NSG --operation Replace --tags miljo=test --query properties.tags

Etter de to Merge-ene har NSG-en begge taggene. Etter Replace står bare miljo=test igjen. az resource tag erstatter også, med mindre du legger til --is-incremental.

4. Delete-lock

Hvorfor: en lock beskytter mot uhell, og den gjelder alle, også Owner. RBAC bestemmer hvem som får gjøre noe. En lock stopper handlingen for alle.

Oppgave: legg en lock av typen Delete på rg-uke03 (Settings → Locks). Prøv så å slette NSG-en, legg til en tag på den, og prøv til slutt å slette hele resource groupen. Slettingene feiler, men taggen går inn. I az heter typen CanNotDelete, og feilen er ScopeLocked.

Vis kommando
az lock create --name ikke-slett --lock-type CanNotDelete -g $RG --query level -o tsv
az network nsg delete --ids $NSG
az tag update --resource-id $NSG --operation Merge --tags app=web --query properties.tags
az group delete --name $RG      # svar y. Den skal feile

5. Read-only-lock

Hvorfor: Read-only stopper all skriving, ikke bare sletting, og det rammer mer enn man tror. Nøklene til en storage account kan for eksempel ikke listes, fordi det er et skrivekall (POST).

Oppgave: endre locken til Read-only. Prøv å legge til en tag på NSG-en og en inbound-regel som tillater port 443. Begge feiler.

Vis kommando
az lock delete --name ikke-slett -g $RG
az lock create --name skrivebeskyttet --lock-type ReadOnly -g $RG --query level -o tsv
az tag update --resource-id $NSG --operation Merge --tags eier=$NAVN --query properties.tags
az network nsg rule create -g $RG --nsg-name "$NAVN-nsg" -n tillat-https --priority 100 `
  --destination-port-ranges 443 --access Allow --protocol Tcp --query name

6. Flytt ressursen

Hvorfor: ressurser kan flyttes mellom resource groups og subscriptions. Regionen blir den samme, men resource-id-en endres, fordi navnet på resource groupen er en del av den. En Read-only-lock stopper flyttingen. En Delete-lock gjør det ikke.

Oppgave: lag rg-uke03-flytt med de samme taggene. Prøv å flytte NSG-en dit (Move → Move to another resource group) mens Read-only-locken står. Bytt så til en Delete-lock, og flytt igjen. Flyttingen tar 2–3 minutter. I portalen kan du gå videre til del B mens den går. Fjern locken når flyttingen er ferdig.

Vis kommando
az group create -n $RG2 -l norwayeast --tags eier=$NAVN kostnadssted=1234 --query name -o tsv
az resource move --destination-group $RG2 --ids $NSG      # feiler med ScopeLocked
az lock delete --name skrivebeskyttet -g $RG
az lock create --name ikke-slett --lock-type CanNotDelete -g $RG --query level -o tsv
az resource move --destination-group $RG2 --ids $NSG      # går
az lock delete --name ikke-slett -g $RG
az resource list -g $RG2 --query "[].{navn:name, region:location, id:id}" -o table

Del B — Azure Policy i Bicep (ca. 25 min)

7. Krev en tag

Hvorfor: RBAC styrer hvem som får gjøre noe. Policy styrer hvordan ressursene skal være, uansett hvem som lager dem. Effekten Deny stopper ressurser som bryter regelen. Ressurser som fantes fra før, blir ikke slettet, bare merket som non-compliant.

Oppgave: tildel den innebygde policyen Require a tag on resources på rg-uke03, med Bicep. Kommandoen under skriver fila, som i uke 2. 

@'
@description('Taggen som kreves på alle ressurser')
param tagName string = 'kostnadssted'

@description('Id-en til den innebygde policyen Require a tag on resources')
param policyDefinitionId string

@description('Default håndhever policyen. DoNotEnforce evaluerer bare')
@allowed([
  'Default'
  'DoNotEnforce'
])
param enforcementMode string = 'Default'

resource krevTag 'Microsoft.Authorization/policyAssignments@2024-04-01' = {
  name: 'krev-${tagName}'
  properties: {
    displayName: 'Krev taggen ${tagName}'
    policyDefinitionId: tenantResourceId('Microsoft.Authorization/policyDefinitions', policyDefinitionId)
    enforcementMode: enforcementMode
    parameters: {
      tagName: {
        value: tagName
      }
    }
  }
}
'@ | Set-Content main.bicep -Encoding utf8
$POLICY = az policy definition list --query "[?displayName=='Require a tag on resources'].name" -o tsv
az deployment group what-if -g $RG --template-file main.bicep --parameters policyDefinitionId=$POLICY
az deployment group create -g $RG --name policy --template-file main.bicep --parameters policyDefinitionId=$POLICY

Oppslaget av policyen tar noen sekunder, fordi det går gjennom alle de innebygde. Prøv så å lage en NSG i rg-uke03 uten tag i portalen. Review + create stopper på policyen. Med kostnadssted går det. I testen virket policyen etter et par sekunder, men det kan ta noen minutter. Går NSG-en uten tag likevel gjennom, vent litt og prøv igjen.

Vis kommando
az network nsg create -g $RG -n "$NAVN-uten-tag"      # RequestDisallowedByPolicy
az network nsg create -g $RG -n "$NAVN-med-tag" --tags kostnadssted=1234 --query NewNSG.name -o tsv

8. Enforcement mode

Hvorfor: med DoNotEnforce evaluerer policyen uten å stoppe noe. Slik tester du en policy i et miljø i drift før du skrur den på. Learn-modulen Azure Policy initiatives spør om dette.

Oppgave: deploy den samme fila med DoNotEnforce, og lag en NSG uten tag. Den går nå. 

az deployment group create -g $RG --name policy --template-file main.bicep `
  --parameters policyDefinitionId=$POLICY enforcementMode=DoNotEnforce
Vis kommando
az network nsg create -g $RG -n "$NAVN-ikke-haandhevet" --query NewNSG.name -o tsv

Start så et compliance-scan. Det tok 5 minutter i testen, så gå videre. Se etter NSG-en under Policy → Compliance etterpå. Den står som Non-compliant. 

az policy state trigger-scan -g $RG --no-wait
az policy state list -g $RG --filter "policyAssignmentName eq 'krev-kostnadssted'" `
  --query "[].{ressurs:resourceId, status:complianceState}" -o table      # etter ca. 5 min

9. Arv taggen (hvis tid)

Hvorfor: effekten Modify endrer ressursen i stedet for å stoppe den. Policyen trenger da en egen identitet med rettigheter. Nye ressurser får taggen med en gang. Ressurser som fantes fra før, må du rette med en remediation task.

Oppgave: tildel Inherit a tag from the resource group if missing med en egen fil, og sett kravet fra steg 7 tilbake til Default. 

@'
@description('Taggen som arves fra resource groupen')
param tagName string = 'kostnadssted'

@description('Id-en til den innebygde policyen Inherit a tag from the resource group if missing')
param policyDefinitionId string

@description('Id-en til rollen Contributor, som policyen trenger for å endre tags')
param roleDefinitionId string

resource arvTag 'Microsoft.Authorization/policyAssignments@2024-04-01' = {
  name: 'arv-${tagName}'
  location: resourceGroup().location
  identity: {
    type: 'SystemAssigned'
  }
  properties: {
    displayName: 'Arv taggen ${tagName} fra resource groupen'
    policyDefinitionId: tenantResourceId('Microsoft.Authorization/policyDefinitions', policyDefinitionId)
    parameters: {
      tagName: {
        value: tagName
      }
    }
  }
}

resource arvRolle 'Microsoft.Authorization/roleAssignments@2022-04-01' = {
  name: guid(arvTag.id, roleDefinitionId)
  properties: {
    principalId: arvTag.identity.principalId
    principalType: 'ServicePrincipal'
    roleDefinitionId: subscriptionResourceId('Microsoft.Authorization/roleDefinitions', roleDefinitionId)
  }
}
'@ | Set-Content arv.bicep -Encoding utf8
$ARV = az policy definition list --query "[?displayName=='Inherit a tag from the resource group if missing'].name" -o tsv
$CONTRIBUTOR = az role definition list --name Contributor --query "[0].name" -o tsv
az deployment group create -g $RG --name arv --template-file arv.bicep --parameters policyDefinitionId=$ARV roleDefinitionId=$CONTRIBUTOR
az deployment group create -g $RG --name policy --template-file main.bicep --parameters policyDefinitionId=$POLICY

Lag en NSG uten tag igjen. Nå går det, og NSG-en har fått kostnadssted fra resource groupen. Modify kjører før Deny, så taggen er på plass når kravet sjekkes. NSG-en fra steg 8 mangler fortsatt taggen. Start en remediation task for den (Policy → Remediation, kryss av for å evaluere på nytt). Den brukte 15–20 minutter i testen, så sjekk taggen like før du rydder opp.

Vis kommando
az network nsg create -g $RG -n "$NAVN-arvet" --query NewNSG.tags
az policy remediation create -g $RG --name arv --policy-assignment arv-kostnadssted `
  --resource-discovery-mode ReEvaluateCompliance --query provisioningState -o tsv
az policy remediation show -g $RG --name arv --query provisioningState -o tsv      # Succeeded etter 15–20 min
az network nsg show -g $RG -n "$NAVN-ikke-haandhevet" --query tags

Del C — Kostnad og management groups (ca. 10 min)

10. Budsjett og Advisor

Hvorfor: et budsjett varsler, men stopper ingenting. Skal noe stoppes, må varselet starte en action group som gjør jobben. Advisor kommer med anbefalinger, blant annet om kostnad.

Oppgave: åpne Cost Management → Budgets for subscriptionen din. Finn beløpet, når det varsles og hvem som får varselet. Se så i Advisor → Cost. Der står det trolig ingenting, fordi subscriptionen er nesten tom.

Vis kommando
az consumption budget list --query "[].{navn:name, belop:amount, periode:timeGrain}" -o table
az consumption budget list --query "[0].notifications" -o json
az advisor recommendation list --category Cost -o table

11. Management groups og arv

Hvorfor: en management group samler subscriptions, og policy og roller som settes der, arves ned. En subscription har bare én forelder, og treet kan ha seks nivåer under root.

Oppgave: åpne Management groups og finn subscriptionen din under Deltakere. Gå så til Policy → Assignments med subscriptionen din som scope. Der står to policyer du ikke har laget. Tillatte regioner er arvet fra mg-deltakere og står i DoNotEnforce. Den andre har Microsoft lagt på Tenant Root Group, og den blokkerer West Europe.

Vis kommando
az account management-group show --name mg-deltakere --expand --query "children[].displayName" -o tsv
$SUB = az account show --query id -o tsv
$TOKEN = az account get-access-token --query accessToken -o tsv
$URL = "https://management.azure.com/subscriptions/$SUB/providers/Microsoft.Authorization/policyAssignments?api-version=2023-04-01&`$filter=atScope()"
(Invoke-RestMethod -Uri $URL -Headers @{ Authorization = "Bearer $TOKEN" }).value.properties |
  Format-List displayName, scope, enforcementMode

az policy assignment list viser ikke policyer som er arvet fra en management group, selv om hjelpeteksten sier det. Derfor går vi rett mot API-et. az rest virker ikke her, fordi Windows PowerShell sender parentesene videre til cmd.exe, som feiler på dem.

Opprydding

Fjern locks først. En resource group med lock kan ikke slettes. Policy-tildelingene og rolletildelingen til policyen forsvinner sammen med resource groupen. 

foreach ($g in $RG, $RG2) { az lock list -g $g --query "[].id" -o tsv | ForEach-Object { az lock delete --ids $_ } }
az group delete --name $RG --yes --no-wait
az group delete --name $RG2 --yes --no-wait

Sjekk etter et par minutter at ingenting står igjen:

az lock list -o table
az group list -o table
