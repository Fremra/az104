Installer Azure CLI (brew install azure-cli på Mac) og kjør labben i zsh eller bash. az-kommandoene er de samme som under. To ting skrives annerledes: profilen og variablene settes slik, og linjeskift er \ i stedet for backtick.

Del A — ARM-mal (Learn, ca. 30 min)

Ha Learn-øvelsen åpen ved siden av. Learn forklarer hva som skal inn i malen. Kommandoene tar du herfra, for Learns er skrevet for bash.

Sett opp resource group og variabler én gang. Navnet på storage accounten må være unikt i hele Azure og bestå av 3–24 små bokstaver og tall. Ingen bindestrek, selv om Learn-teksten sier at det er lov. Svein-Tore skriver sveintore. Vi setter det sammen av st (for storage account), fornavnet ditt og uke01. Olav får altså st + olav + uke01 = stolavuke01. 

$RG = "rg-uke01"
$ST = "st<fornavn>uke01"       # legg til tall hvis navnet er tatt
$today = Get-Date -Format "yyyy-MM-dd"
az group create --name $RG --location norwayeast

Variablene gjelder bare dette vinduet. Åpner du et nytt, setter du dem på nytt.

Learn bruker az configure --defaults group=.... Vi gjør ikke det: den innstillingen blir liggende i CLI-profilen og slår inn i neste ukes lab. Vi sender heller -g $RG hver gang.

1. Tom mal

Hvorfor: for å se hva en mal består av før det er noe i den, og for å få bekreftet at innlogging, resource group og verktøy virker. En mal uten ressurser er også en gyldig deploy.

Steg 1 og 2 følger Learn-øvelsen Create and deploy an Azure Resource Manager template.

Lag en mappe til labben og åpne den i VS Code. Bli i det samme vinduet, for variablene dine ligger der. 

mkdir uke-01
cd uke-01
code .

Virker ikke code, åpner du mappa fra VS Code med File → Open Folder. Lag så en ny fil med navnet azuredeploy.json, lim inn skjelettet under og lagre. 

{
  "$schema": "https://schema.management.azure.com/schemas/2019-04-01/deploymentTemplate.json#",
  "contentVersion": "1.0.0.0",
  "parameters": {},
  "functions": [],
  "variables": {},
  "resources": [],
  "outputs": {}
}

$schema, contentVersion og resources er påkrevd. Resten er valgfritt og står tomt til vi trenger det: ressursen kommer i steg 2, parameterne i steg 3–4 og output i steg 5.

Deploy malen fra PowerShell-vinduet:

az deployment group create -g $RG --name blanktemplate-$today --template-file azuredeploy.json

Kommandoen svarer med en lang JSON. "provisioningState": "Succeeded" betyr at det gikk bra. Se så i portalen under resource groupen → Deployments. Der ligger én vellykket deploy og ingen ressurser. Azure fører altså historikk over hver deploy, også en tom en.

2. Legg til storage account

Hvorfor: for å se hvordan én ressurs beskrives i en mal: type, apiVersion, name, location, kind og sku. Malen sier hva som skal finnes, og Resource Manager sørger for at det blir slik.

Bytt ut "resources": [], i malen med blokken under. Den er lik Learns, med to endringer: navnet er ditt eget i stedet for storageaccount1, og SKU-en er Standard_GRS i stedet for Standard_LRS. Skriv inn det samme navnet som du satte i $ST, begge steder. 

  "resources": [
    {
      "type": "Microsoft.Storage/storageAccounts",
      "apiVersion": "2025-01-01",
      "name": "st<fornavn>uke01",
      "tags": {
        "displayName": "st<fornavn>uke01"
      },
      "location": "[resourceGroup().location]",
      "kind": "StorageV2",
      "sku": {
        "name": "Standard_GRS"
      }
    }
  ],

Lagre fila og deploy:

az deployment group create -g $RG --name addstorage-$today --template-file azuredeploy.json

Hvorfor GRS allerede her

Learn oppretter storage accounten som Standard_LRS her, og deployer den på nytt med storageSKU=Standard_GRS i steg 4. Det byttet er en geo-konvertering, og så lenge den pågår, kan ikke storage accounten slettes. az group delete i oppryddingen ser da ut til å virke, men resource groupen blir stående, med PendingTransactionAlreadyExists i Activity log. I testen 29.09 var slettingen blokkert i nesten en halvtime. Med GRS fra starten blir det ingen konvertering.

3. Parameter for navnet

Hvorfor: navnet står hardkodet i malen, så den kan bare brukes én gang. Med en parameter kan samme mal brukes av alle, med hvert sitt navn. Verdien gis når du deployer.

Steg 3–5 følger Learn-øvelsen Add parameters and outputs to your Azure Resource Manager template. Bytt ut "parameters": {}, i malen med dette: 

  "parameters": {
    "storageName": {
      "type": "string",
      "minLength": 3,
      "maxLength": 24,
      "metadata": {
        "description": "The name of the Azure storage resource"
      }
    }
  },

Bruk så parameteren i ressursen, i stedet for navnet du skrev inn i steg 2:

      "name": "[parameters('storageName')]",
      "tags": {
        "displayName": "[parameters('storageName')]"
      },

Lagre fila og deploy. Navnet gir du nå i kommandoen:

az deployment group create -g $RG --name addnameparameter-$today `
  --template-file azuredeploy.json --parameters storageName=$ST

Tegnet sist på linja er en backtick. Den sier til PowerShell at kommandoen fortsetter på neste linje, og den må stå helt sist, uten mellomrom etter.

4. Parameter for SKU, med allowedValues

Hvorfor: allowedValues begrenser hva den som deployer, kan velge, og defaultValue gjør parameteren valgfri. En verdi utenfor lista stoppes ved valideringen, før noe endres i Azure.

Legg til en parameter til i parameters, etter storageName. Husk komma mellom de to. 

    "storageSKU": {
      "type": "string",
      "defaultValue": "Standard_LRS",
      "allowedValues": [
        "Standard_LRS",
        "Standard_GRS",
        "Standard_RAGRS",
        "Standard_ZRS",
        "Premium_LRS",
        "Premium_ZRS",
        "Standard_GZRS",
        "Standard_RAGZRS"
      ]
    }

Bruk den i ressursen, i stedet for Standard_GRS:

      "sku": {
        "name": "[parameters('storageSKU')]"
      }

Lagre fila og deploy:

az deployment group create -g $RG --name addSkuParameter-$today `
  --template-file azuredeploy.json --parameters storageName=$ST storageSKU=Standard_GRS

Storage accounten er alt GRS fra steg 2, så ingenting endres. Poenget er neste kommando: kjør den samme med storageSKU=Basic. Den skal feile. Legg merke til at feilen kommer ved validering, før noe endres i Azure.

5. Output

Hvorfor: noen verdier finnes først når ressursen er opprettet, som endepunktene til storage accounten. Output gir dem tilbake fra deployen, så et skript eller en annen mal kan bruke dem.

Bytt ut "outputs": {} nederst i malen med dette:

  "outputs": {
    "storageEndpoint": {
      "type": "object",
      "value": "[reference(parameters('storageName')).primaryEndpoints]"
    }
  }

Lagre fila og deploy:

az deployment group create -g $RG --name addoutputs-$today `
  --template-file azuredeploy.json --parameters storageName=$ST storageSKU=Standard_GRS `
  --query properties.outputs

Samme output ligger i portalen under Deployments → addoutputs → Outputs.

Del B — Bicep (ca. 25 min)

6. Kjør samme mal på nytt, med what-if

Hvorfor: for å se at en mal trygt kan kjøres flere ganger. what-if viser hva en deploy ville endret, uten å gjøre det. 

az deployment group what-if -g $RG --template-file azuredeploy.json `
  --parameters storageName=$ST storageSKU=Standard_GRS

Forventet resultat: NoChange (og kanskje noen Ignore). En mal som kjøres på nytt uten endringer, endrer ingenting. Det er ett av kunnskapsspørsmålene i Learn.

7. Gjør ARM om til Bicep

Hvorfor: Bicep er samme mal i en enklere syntaks. Studieguiden ber deg kunne gjøre en ARM-mal om til en Bicep-fil, og dette er kommandoen for det. 

az bicep decompile --file azuredeploy.json

Du får azuredeploy.bicep. Åpne den ved siden av azuredeploy.json og sammenlign de to. Det er samme mal i to språk, og Bicep-fila er klart kortere.

Se på siste linje, output. I JSON sto det [reference(parameters('storageName')).primaryEndpoints]. Hva står det i Bicep, og hva peker storage på?

8. Endre Bicep-fila og deploy den

Hvorfor: studieguiden ber deg kunne endre en eksisterende Bicep-fil. Her ser du også hva en deploy gjør med en ressurs som finnes fra før.

Legg til en tag i tags, f.eks. uke: '1'. Se hva som vil skje, og deploy:

az deployment group what-if -g $RG --template-file azuredeploy.bicep `
  --parameters storageName=$ST storageSKU=Standard_GRS

az deployment group create -g $RG --name bicep-$today --template-file azuredeploy.bicep `
  --parameters storageName=$ST storageSKU=Standard_GRS

what-if skal vise Modify på storage accounten, med den nye tag-en. Prøv også å fjerne storageSKU=Standard_GRS fra kommandoen og kjør what-if igjen. Hva skjer med SKU-en, og hvorfor?

9. Incremental mot Complete (hvis tid)

Hvorfor: de to deployment-modusene behandler ressurser utenfor malen helt ulikt. Her ser du forskjellen uten å slette noe, fordi what-if bare viser hva Complete ville fjernet.

Lag en ressurs som ikke står i malen. En network security group (NSG) er gratis:

az network nsg create -g $RG --name nsg-utenfor-malen --location norwayeast

Har ingen brukt nettverk i subscriptionen før, får du Resource provider 'Microsoft.Network' ... is not registered. We are registering for you. Det er normalt. Resource providers registreres per subscription, og CLI og malene gjør det automatisk. Microsoft.Storage ble registrert på samme måte i steg 2. 

az deployment group what-if -g $RG --template-file azuredeploy.bicep `
  --parameters storageName=$ST storageSKU=Standard_GRS --mode Complete

I Complete-modus sletter Azure alt i resource groupen som ikke står i malen, og what-if viser Delete på NSG-en. Standard er Incremental, og da blir den stående. Ikke kjør Complete på ordentlig. Microsoft skal fase den ut og anbefaler deployment stacks i stedet.

Se også portalen → resource groupen → Export template. Det er et øyeblikksbilde av tilstanden nå, med NSG-en og hardkodede verdier. Tell ressursene: du deployet én storage account, men eksporten tar også med blob-, file-, queue- og table-tjenestene under den. Deployments → addoutputs → Template er derimot malen slik den ble deployet.
