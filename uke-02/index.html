Brukere, grupper og RBAC

Learn-øvelsene i Create, configure, and manage identities foregår i portalen og dekker bare en del av studieguiden. Her gjør vi det samme, og mer, med az, og vi sjekker resultatet i portalen. Del A er Entra ID: brukere, grupper, lisenser og gjester. Del B er RBAC i Bicep. Fasiten ligger under labben.

Alle deler én tenant. Subscriptionen er din, men brukere og grupper havner i den samme katalogen som alle andre sine. Derfor starter alt du lager, med fornavnet ditt, og du rører bare dine egne objekter. Du har rollen User Administrator i tenanten denne uka og neste.

Før møtet

Labben er bare az-kommandoer, så den virker både lokalt og i Cloud Shell. Velg ett av dem.

Lokalt: samme verktøy og innlogging som i uke 1. Åpne et nytt PowerShell-vindu og bruk kursprofilen: 

$env:AZURE_CONFIG_DIR = "$HOME\.azure-az104"
az account show --query "{subscription:name, bruker:user.name}" -o table

Ser du ikke AZ-104 <Navn>, kjør az login --tenant <lab-tenanten> og az account set --subscription "AZ-104 <Navn>" som i uke 1.

Cloud Shell: åpne portal.azure.com i et privat vindu og logg inn med lab-brukeren. Klikk >_ og velg PowerShell. No storage account required holder. Du er allerede logget inn, så hopp over $env:-linja og az login. Sjekk med az account show som over. Sesjonen lukkes etter 20 minutter uten aktivitet, og da forsvinner både variablene og filene. Se Vanlige feil.

Lag så en mappe til labben, og sett variablene én gang:

mkdir uke-02
cd uke-02
$NAVN = "<fornavn>"      # små bokstaver, f.eks. svein-tore
$DOMENE = az rest --method get --url "https://graph.microsoft.com/v1.0/domains" --query "value[?isDefault].id" -o tsv
$RG = "rg-uke02"
$DOMENE

Den siste linja skal vise domenet til lab-tenanten. Brukernavn i Entra ID slutter på det.

Flere av stegene bruker az rest, som sender et kall rett til Microsoft Graph. Det er API-et bak Entra ID. az ad dekker det vanligste, men ikke lisenser, dynamiske grupper og gjester. Når kallet trenger en JSON-body, lager vi den i PowerShell og skriver den til en fil. Windows PowerShell ødelegger anførselstegn i JSON som sendes rett på kommandolinja, og fila virker likt overalt.

Del A — Entra ID (ca. 30 min)

0. Sjekk rollen din

Hvorfor: Entra ID og Azure har hvert sitt rollesystem. Owner på subscriptionen gir deg ingenting i katalogen. For å lage brukere trenger du en rolle i Entra ID. 

az rest --method get --url "https://graph.microsoft.com/v1.0/me/memberOf/microsoft.graph.directoryRole" `
  --query "value[].displayName" -o tsv

Du skal se User Administrator. Står det ingenting, si fra før du går videre.

1. Opprett en bruker

Hvorfor: brukeren er grunnobjektet i resten av labben. Usage location må være satt før brukeren kan få lisens. Department bruker vi til en dynamisk gruppe i steg 4. 

$PASSORD = "Uke02-" + (Get-Random -Minimum 10000 -Maximum 99999) + "!"
$CHRIS = az ad user create --display-name "Chris Green ($NAVN)" `
  --user-principal-name "$NAVN-chris@$DOMENE" --password $PASSORD `
  --force-change-password-next-sign-in true --query id -o tsv

@{ usageLocation = "NO"; department = "$NAVN-marketing" } | ConvertTo-Json | Set-Content chris.json
az rest --method patch --url "https://graph.microsoft.com/v1.0/users/$CHRIS" --body "@chris.json"

az ad user create har ikke flagg for usage location og department, så de settes med az rest. Åpne Entra-portalen (entra.microsoft.com) → Users og finn Chris Green (<fornavn>). Under Properties skal du se usage location og department.

2. Sikkerhetsgruppe med medlem og eier

Hvorfor: grupper med tildelt medlemskap (assigned) er den vanligste typen. En eier kan styre gruppen uten å være medlem av den, og det spør eksamen om. 

$GRUPPE = az ad group create --display-name "$NAVN-marketing" --mail-nickname "$NAVN-marketing" --query id -o tsv
az ad group member add --group $GRUPPE --member-id $CHRIS
$MEG = az ad signed-in-user show --query id -o tsv
az ad group owner add --group $GRUPPE --owner-object-id $MEG

az ad group member list --group $GRUPPE --query "[].displayName" -o tsv
az ad group owner list --group $GRUPPE --query "[].userPrincipalName" -o tsv

Chris er medlem, og du er eier. az ad group create lager alltid en sikkerhetsgruppe. En Microsoft 365-gruppe, som Learn-øvelsen lager, må du lage i portalen eller med Graph.

3. Lisens via gruppen

Hvorfor: lisenser deles ut til grupper, ikke bruker for bruker. Den som blir medlem, får lisensen, og den som går ut, mister den. Gruppebasert lisensiering krever minst Entra ID P1, og tenanten har en P2-prøve. 

$SKU = az rest --method get --url "https://graph.microsoft.com/v1.0/subscribedSkus" `
  --query "value[?skuPartNumber=='AAD_PREMIUM_P2'].skuId" -o tsv
@{ addLicenses = @(@{ skuId = $SKU }); removeLicenses = @() } | ConvertTo-Json -Depth 3 | Set-Content lisens.json
az rest --method post --url "https://graph.microsoft.com/v1.0/groups/$GRUPPE/assignLicense" --body "@lisens.json" --query displayName -o tsv

Vent et minutt, og se så hvor lisensen til Chris kommer fra:

az rest --method get --url "https://graph.microsoft.com/v1.0/users/$CHRIS`?`$select=licenseAssignmentStates" `
  --query "licenseAssignmentStates[].{viaGruppe:assignedByGroup, status:state}" -o table

viaGruppe skal være id-en til $GRUPPE, og status Active. Er tabellen tom, vent litt og kjør igjen. Backtickene foran ? og $select hindrer PowerShell i å lese $select som en variabel. I portalen: Chris → Licenses. Der står det at lisensen er arvet fra gruppen.

4. Dynamisk gruppe

Hvorfor: en dynamisk gruppe finner medlemmene selv ut fra en regel på brukerens egenskaper. Ingen legger dem inn. Det krever P1, og det kan ta litt tid før endringer slår inn. 

@{
  displayName = "$NAVN-salg"; mailNickname = "$NAVN-salg"
  mailEnabled = $false; securityEnabled = $true
  groupTypes = @("DynamicMembership")
  membershipRule = "user.department -eq `"$NAVN-salg`""
  membershipRuleProcessingState = "On"
} | ConvertTo-Json | Set-Content salg.json
$SALG = az rest --method post --url "https://graph.microsoft.com/v1.0/groups" --body "@salg.json" --query id -o tsv

Gruppen er tom, fordi Chris er i marketing. Flytt ham til salg:

@{ department = "$NAVN-salg" } | ConvertTo-Json | Set-Content chris.json
az rest --method patch --url "https://graph.microsoft.com/v1.0/users/$CHRIS" --body "@chris.json"
az ad group member list --group $SALG --query "[].displayName" -o tsv

Kjør den siste linja igjen til Chris dukker opp. I testen tok det under et halvt minutt. Prøv så å legge deg selv inn i gruppen: 

az ad group member add --group $SALG --member-id $MEG

Det skal feile. Medlemskapet i en dynamisk gruppe styres bare av regelen, så heller ikke en administrator kan legge inn noen manuelt. Feilmeldingen sier «Insufficient privileges», og det er misvisende.

5. Gjestebruker

Hvorfor: eksterne brukere (B2B) får en egen konto i katalogen din, men logger inn med sin egen identitet. Studieguiden har dem som eget punkt. 

@{
  invitedUserEmailAddress = "$NAVN.az104.gjest@outlook.com"
  invitedUserDisplayName = "Gjest ($NAVN)"
  inviteRedirectUrl = "https://myapps.microsoft.com"
  sendInvitationMessage = $false
} | ConvertTo-Json | Set-Content gjest.json
$GJEST = az rest --method post --url "https://graph.microsoft.com/v1.0/invitations" --body "@gjest.json" --query invitedUser.id -o tsv

az rest --method get --url "https://graph.microsoft.com/v1.0/users/$GJEST`?`$select=userPrincipalName,userType,externalUserState" `
  --query "{upn:userPrincipalName, brukertype:userType, status:externalUserState}" -o table

Adressen er oppdiktet, og det sendes ingen e-post. Se på brukernavnet: _outlook.com#EXT#@.... Brukertypen er Guest, og status er PendingAcceptance til invitasjonen er innløst. example.com blir avvist, så vi bruker outlook.com.

6. Slett og gjenopprett

Hvorfor: en slettet bruker ligger i Deleted users i 30 dager og kan hentes tilbake. Spørsmålet er hva som følger med tilbake. 

az ad user delete --id $CHRIS
az rest --method get --url "https://graph.microsoft.com/v1.0/directory/deletedItems/microsoft.graph.user" --query "value[].displayName" -o tsv
az rest --method post --url "https://graph.microsoft.com/v1.0/directory/deletedItems/$CHRIS/restore" --query displayName -o tsv
az ad user get-member-groups --id $CHRIS --query "[].displayName" -o tsv

Chris er tilbake i begge gruppene, og lisensen kommer tilbake via gruppen. Kjør kommandoen fra steg 3 for å se det. Sikkerhetsgrupper har ingen papirkurv: de er borte med en gang når de slettes. Det har bare Microsoft 365-grupper.

SSPR · demo

Hvorfor: selvbetjent tilbakestilling av passord (SSPR) står i studieguiden. Innstillingen gjelder hele tenanten, så Jan viser den på skjermen i stedet for at alle endrer den.

Entra → Password reset → Properties: Jan slår på SSPR for gruppen sspr-demo, ikke for alle. Under Authentication methods velger du hvor mange metoder som kreves. Under Registration bestemmer du om brukerne må registrere seg ved neste innlogging.

Del B — RBAC i Bicep (ca. 25 min)

7. Gi gruppen Reader på en resource group

Hvorfor: en rolletildeling er en ressurs med tre deler: hvem (principal), hva (rolledefinisjon) og hvor (scope). I Bicep ser du alle tre på ett sted. Gi tilgang til grupper, ikke personer.

Lag main.bicep i mappa. Kommandoen under skriver fila, så du trenger ingen editor. Den virker også i Cloud Shell. Lokalt kan du åpne fila i VS Code etterpå, så viser Bicep-utvidelsen hva hver del er. 

@'
@description('Object-id-en til gruppen som skal ha rollen')
param groupId string

@description('Reader. Id-en til en innebygd rolle er den samme i alle tenanter')
param roleDefinitionId string = 'acdd72a7-3385-48ef-bd42-f606fba81ae7'

resource readerForGroup 'Microsoft.Authorization/roleAssignments@2022-04-01' = {
  name: guid(resourceGroup().id, groupId, roleDefinitionId)
  properties: {
    principalId: groupId
    principalType: 'Group'
    roleDefinitionId: subscriptionResourceId('Microsoft.Authorization/roleDefinitions', roleDefinitionId)
  }
}
'@ | Set-Content main.bicep -Encoding utf8
az group create --name $RG --location norwayeast
az deployment group what-if -g $RG --template-file main.bicep --parameters groupId=$GRUPPE
az deployment group create -g $RG --name rbac --template-file main.bicep --parameters groupId=$GRUPPE

what-if viser Create på én roleAssignment. Kjør what-if én gang til etter deployen. Nå skal den vise Nochange. Navnet på en rolletildeling må være en GUID, og guid() lager den samme hver gang ut fra de samme verdiene. Det er derfor deployen kan kjøres på nytt uten å feile. Finn rolle-id-er med az role definition list --name Reader --query "[].name" -o tsv.

8. Tolk tilgangen

Hvorfor: studieguiden sier «interpret access assignments». Tilgang via en gruppe er lett å overse. 

az role assignment list --assignee $CHRIS --all -o table
az role assignment list --assignee $CHRIS --all --include-groups `
  --query "[].{rolle:roleDefinitionName, via:principalName, scope:scope}" -o table

Den første er tom, fordi Chris ikke har noen tildeling selv. Den andre viser Reader via <fornavn>-marketing. Se det samme i portalen: rg-uke02 → Access control (IAM) → Check access → søk opp Chris. Prøv også fanen Role assignments, og se at du selv står der som Owner, arvet fra subscriptionen.

9. Scope og arv (hvis tid)

Hvorfor: en rolle på subscriptionen arves av alle resource groups og ressurser under den. Det er grunnen til at man gir tilgang så lavt som mulig. 

$SUB = az account show --query id -o tsv
az role assignment create --assignee-object-id $GRUPPE --assignee-principal-type Group `
  --role Reader --scope "/subscriptions/$SUB"
az role assignment list --assignee $CHRIS --all --include-groups --query "[].{rolle:roleDefinitionName, scope:scope}" -o table

Nå har Chris Reader to steder. Tildelingen på resource groupen er overflødig, siden den på subscriptionen dekker den. Slett tildelingen på subscriptionen igjen med en gang. Kommandoen står under Opprydding.

Opprydding

Rydd i tenanten også, ikke bare i subscriptionen. Ellers ligger brukerne og gruppene dine der for alle andre. Fjern først lisensen fra gruppen. En gruppe med lisens kan ikke slettes. 

$SUB = az account show --query id -o tsv
az role assignment delete --assignee $GRUPPE --role Reader --scope "/subscriptions/$SUB"   # bare hvis du gjorde steg 9
az group delete --name $RG --yes --no-wait

@{ addLicenses = @(); removeLicenses = @($SKU) } | ConvertTo-Json | Set-Content lisens.json
az rest --method post --url "https://graph.microsoft.com/v1.0/groups/$GRUPPE/assignLicense" --body "@lisens.json" --query displayName -o tsv
az ad group delete --group "$NAVN-marketing"
az ad group delete --group "$NAVN-salg"
az ad user delete --id $CHRIS
az ad user delete --id $GJEST

Brukerne ligger nå i Deleted users i 30 dager. Slett dem for godt:

az rest --method delete --url "https://graph.microsoft.com/v1.0/directory/deletedItems/$CHRIS"
az rest --method delete --url "https://graph.microsoft.com/v1.0/directory/deletedItems/$GJEST"

Sjekk at ingenting med navnet ditt står igjen. Det eneste som skal stå, er din egen bruker:

az ad group list --query "[?starts_with(displayName, '$NAVN-')].displayName" -o tsv
az ad user list --query "[?starts_with(userPrincipalName, '$NAVN')].userPrincipalName" -o tsv
az group list -o table
